# Limitations — Stated Honestly

## Dataset limitations

1. **LFW-derived benchmark, not a native face-anti-spoofing corpus.** All bonafide face pixels originate from LFW (`huang2007lfw`), a face-verification dataset with no attack labels of its own; every attack class in this benchmark is synthesised, not captured. See `DATASET.md` for the explicit original-vs-constructed breakdown.
2. **Synthetic/constructed attack generation.** All six non-adversarial attack classes are produced by hand-designed image-processing pipelines (`xuad/data/attacks.py`), not real presentation-attack captures or real deepfake generators. This is a controlled, difficulty-calibrated simulation, and results on it should not be read as equivalent to performance on captured physical attacks or outputs of real generative models (e.g., actual diffusion/GAN-based face swaps).
3. **No external, real-world corpus generalization was established this session.** `PROJECT_STATE.md` (an earlier campaign) states that adapters exist for nine public corpora but were regression-tested only against synthetic mock fixtures, and that FaceForensics++ external validation was prepared but never run. **Nothing in this session's work changes that status** — this session ran only the constructed benchmark (protocol P1, plus one P2.replay fold). Any generalization claim beyond this benchmark is unsupported.
4. **A genuine, code-verified design overlap exists between some attack classes.** `mask3d` and `synth` both apply `cv2.bilateralFilter` as their primary artifact with overlapping parameter ranges (`xuad/data/attacks.py:216-217` vs. `333-334`) — this is a designed-in property of the benchmark, not solely a model limitation, and it is part of why this pair remains one of the hardest confusions across every model trained this session.

## Model / claim limitations

5. **No claim of state-of-the-art accuracy.** This session's numbers were never compared head-to-head against an external system on a shared, standard benchmark. The final ensemble's 96.24% is the best result **within this project's own experiment series**, not a comparison to published external results.
6. **Ensemble test-subset selection caveat.** The final ensemble's combination *weights* are a fixed, uniform 1/7 average, never fit to any data (verified programmatically). However, the *choice of which 7 of 8 trained models to include* (all except the original baseline) was originally made by comparing candidate subsets' accuracy **on the test set** during an emergency analysis — a mild form of test-set model selection, disclosed in full in `results_final/FINAL_RESULTS_REPORT.md` §4. A validation-set check (96.58% val accuracy for the same 7-model set) partially corroborates the selection wasn't a pure test-set artifact, but does not eliminate the original dependency.
7. **Final ensemble ECE = 8.891**, worse than any individual constituent model (which ranged 3.8–5.5). Averaging several differently-calibrated models' probability vectors is not guaranteed to preserve calibration even when accuracy improves. Raw ensemble confidence scores should not be read as calibrated probabilities without further correction (e.g., temperature scaling), which was not performed.
8. **Ensemble localisation is inherited from the strongest single constituent model, not produced by the ensemble itself.** The saved prediction files for every model in this project store only classification probabilities, vacuity, and risk — never the localisation map — so there is no principled way to "average" segmentation output across the 7 constituent models within this session's scope. Localisation numbers reported alongside the final ensemble (`loc_IoU=0.8887`, `loc_Dice=0.9349`) belong to `results_region_pooled_detached/` specifically and should always be labeled as such, not attributed to "the ensemble."
9. **Adaptive Quantum Attention is a classical, simulated mechanism**, not an implementation on quantum hardware — real-valued amplitude encoding and real orthogonal Givens rotations computed on ordinary CPU hardware. Any wording implying quantum computation, quantum speedup, or quantum advantage would be inaccurate; see `CLAIMS_AUDIT.md`.
10. **Bonafide recall trade-off in the best single model.** `results_region_pooled_detached/` regressed bonafide recall slightly relative to the primary reference (99.08%→98.75%) even though its overall accuracy and several other metrics improved — a real, disclosed trade-off, not eliminated by the final ensemble's better bonafide recall (99.58%).

## Evaluation-protocol limitations

11. **Single train/val/test split, single random seed (0) for every experiment.** No cross-validation or multi-seed variance estimate exists for any reported number; single-run point estimates should be read with that in mind, though McNemar's test was used throughout to check whether *pairwise* differences between specific model pairs were statistically distinguishable from noise.
12. **Protocol coverage is narrow within this session.** Only protocol P1 (closed-set) was run for the full accuracy-improvement series; one P2.replay (leave-one-attack-out) fold exists as a single exploratory data point, at a different (6-epoch) training budget, not directly comparable to the 12-epoch P1 series.
13. **The earlier project campaign's broader evaluation (P2 all-family, P3 cross-domain, 7 component ablations, localisation-vs-baseline, explanation faithfulness, attention-gate analysis, compute-cost comparison) used a different dataset composition and training budget than this session's benchmark** and was not reproduced or re-verified this session. If those results are referenced in the paper, they must be clearly attributed to the earlier campaign and not presented as reproduced or as pertaining to the 96.24% ensemble result.
14. **CPU-only training throughout.** All experiments this session ran on CPU hardware with a 12-epoch budget (6 for the one P2 fold); no claim about training-time scalability to larger models, larger datasets, or GPU throughput was tested.
15. **Risk-calibration coefficients are untrained policy values**, not learned from any supervised signal (`risk` is never consumed by the training loss — verified this session). Any risk-band numbers reported should be described as a configurable operating policy, not a validated quantitative result.
