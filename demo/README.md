# X-UAD Demo — Single-Image Inference

A live, single-image demonstration of the trained X-UAD detector, for showing to a professor or other audience. This wraps the project's **existing** model class, face-cropping function, and explanation pipeline — it does not reimplement any of them.

## What X-UAD does

X-UAD is a single neural network that looks at one face image and, in one forward pass:

1. **Classifies** it into one of 8 categories — a genuine capture, or one of 6 synthesised attack types, or an adversarial perturbation: `bonafide, print, replay, mask3d, faceswap, reenact, synth, adversarial`.
2. **Reports a confidence and an uncertainty ("vacuity")** score via a Dirichlet-evidential head, rather than a plain softmax — the model can say "I don't know" instead of forcing a confident guess.
3. **Localises the evidence** — a 56×56 heatmap of *where* in the face the attack signal was found, learned from pixel-level supervision during training.
4. **Explains itself in plain language**, generated by a deterministic rule-based reasoner that only ever states numbers actually present in the model's own output — it cannot hallucinate a detail that isn't there.

## Exact setup steps

From the project root (`X-UAD-final/`):

```bash
# if the project's own environment isn't already active, install the demo's
# (small) dependency set -- these are already satisfied if you've run
# anything else in this project, since they're a subset of requirements.txt
pip install -r demo/requirements.txt
```

No other setup is needed. The demo loads an existing, already-trained checkpoint read-only; it does not train, download, or generate anything.

## Exact command to run the demo

```bash
python demo/run_demo.py --image <path/to/your/image.jpg>
```

Optional flags:

| Flag | Default | Meaning |
|---|---|---|
| `--ckpt` | `results_region_pooled_detached/xuad_P1_regionpool_detached.pt` | which checkpoint to load |
| `--out` | `demo/outputs` | where to save the per-image report |
| `--no-basis-naming` | off | skip the optional quantum-mode-naming step (see below) — makes the run slightly faster |
| `--threads` | 2 | CPU thread count |

## Expected input format

Any single image file OpenCV can read (JPEG, PNG, BMP, …), containing one visible face. The image does **not** need to be pre-cropped — the demo runs face detection itself. If no face is found, a centred fallback crop is used and the demo prints a warning; results on a fallback crop are less reliable.

## Which checkpoint is used, and why

`results_region_pooled_detached/xuad_P1_regionpool_detached.pt` — the **best single model** produced by this project's experiment series:

- 94.583% 8-class test accuracy (the highest of any single trained model — see `results_final/RESULTS_TABLES.md` Table 1).
- The best localisation quality of any model (`loc_IoU = 0.8887`, `loc_Dice = 0.9349`).
- A full Dirichlet-evidential uncertainty head.

The project's other, higher-accuracy result (96.24%) is a 7-model **ensemble** (`results_final/`) — it has no single checkpoint file and, critically, no native localisation output (the saved predictions for every ensemble member store only classification probabilities, not localisation maps), so it cannot cleanly drive a single-image demo that shows localisation. The single best-localising, best-single-model checkpoint was chosen instead, per the brief.

## Which model components are actually active

Every part of the architecture runs on every call — nothing is disabled for the demo:

- **CDC stem + spectral branch + 4 Adaptive-Quantum-Attention transformer blocks** (`xuad/models/xuad.py`, `xuad/models/aqa.py`) — produce the classification feature.
- **`RegionPool`** (`xuad/models/heads.py`) — this checkpoint was trained with the region-pooled localisation-reuse mechanism (`region_pool=True`), so the demo must build the model with that same flag or the saved weights will not load. This is why the demo does **not** use `xuad/models/xuad.py`'s bare default constructor.
- **Evidential (Dirichlet) classification head** — produces the class probabilities and the vacuity/uncertainty score shown in the report.
- **Localisation head** — produces the 56×56 evidence map shown as a heatmap.
- **Risk calibrator** — produces the risk score/band shown in the headline.
- **`GroundedReasoner`** (`xuad/xai/reasoning.py`) — turns the above into the natural-language explanation. It is a rule-based, zero-hallucination-by-construction text generator: every sentence it can produce is guarded by a real numeric field of the evidence record; it is not a language model and makes no network call.

## How localisation and uncertainty are actually produced

- **Uncertainty (vacuity)**: the evidential head predicts a Dirichlet concentration `alpha = 1 + E·pi`, `S = K + E`; vacuity `= K/S`. Low vacuity means strong, concentrated evidence for one class; vacuity near 1 means the evidence doesn't clearly match any trained class. This is a genuine model output, computed from the same forward pass as the classification, not a post-hoc heuristic.
- **Localisation**: the model's stem produces multi-scale feature maps; a small FPN-style decoder (`LocalisationHead`) fuses them into a 56×56 sigmoid map, trained during the project's experiments against the pixel-level attack mask that the benchmark's own attack-synthesis code produced for each sample. The demo upsamples this map to the input crop's size and overlays it as a heatmap — this is the model's own learned output, not a saliency approximation computed after the fact.
- **Preprocessing** exactly reproduces the two-step pipeline used to build every training/test sample (`xuad/data/build_benchmark.py`, `xuad/data/dataset.py`): a Haar-cascade face crop to 128×128 with a 12% margin, then a deterministic centre-crop to 112×112 — **not** an approximate single-step crop. This was verified to matter: an earlier, simpler single-step version of this demo was found, by direct comparison against the real evaluation pipeline on real project samples, to shift the model's output away from what it actually produces during evaluation, and was corrected before this demo was finalised.

## Limitations, stated honestly

- This checkpoint's own, previously-measured accuracy is 94.58% — it **will** misclassify roughly 1 in 17 real test samples, and its known weakest classes are `faceswap` and `reenact` (see `results_final/RESULTS_TABLES.md`). A demo run on a hard sample can and did, during this demo's own verification (see below), produce a genuinely uncertain or wrong prediction — this is authentic model behaviour, not a bug, and the vacuity/confidence numbers shown are designed to surface exactly that honestly rather than hide it.
- Face detection is a plain Haar cascade (`xuad/data/faces.py`), not a modern landmark-based detector — an unusual pose, occlusion, or low-quality image may fail detection, triggering the fallback-crop warning.
- The model was trained exclusively on this project's own constructed, LFW-derived benchmark (see `results_final/paper_material/DATASET.md`); performance on a real photograph or a real presentation attack/deepfake it wasn't trained on is not established.
- No claim beyond what this single checkpoint was actually measured to do — see `results_final/paper_material/CLAIMS_AUDIT.md` for what can and cannot be safely claimed about X-UAD as a whole.

## How the test samples were chosen (for anyone re-running the verification below)

Three images were exported from this project's own test-split arrays (`data/A_x.npy`) to real PNG files purely so the demo could be exercised end-to-end on real project data (no raw standalone image files exist elsewhere in the project). Selection used the **same rule already used elsewhere in this codebase** (`scripts/demo.py`): the sample at position `len(class)//3` within each requested class, ordered by dataset index — chosen by class position only, **before** ever running the model, so the choice could not be biased toward a flattering result.
